# الأمان — دليل المراجعة قبل الإنتاج

## 1) المصادقة

| العنصر | التنفيذ |
| --- | --- |
| تخزين كلمة المرور | `scrypt` (N=16384, r=8, p=1) مع Salt عشوائي 16 بايت |
| كلمات المرور القديمة | نص صريح في البذرة → تُرقّى تلقائياً عند الإقلاع وأول دخول |
| التوكن | JWT HS256: Access افتراضياً 12 ساعة، Refresh 30 يوماً |
| إبطال الجلسات | حقل `pv` (password version) داخل التوكن يُقارن بقيمة المستخدم |
| تغيير كلمة المرور | يتطلب كلمة المرور الحالية، ويُبطل التوكنات السابقة |
| تحديد المحاولات | 10 محاولات لكل مستخدم/5 دقائق، 80 لكل IP/5 دقائق، 60 تجديد/دقيقة |

### قبل الإنتاج
- [ ] `SECRET_KEY` عشوائي بطول 32+ حرفاً (Render: Generate).
- [ ] تغيير كلمة مرور `admin` وكلمات المرور التجريبية.
- [ ] تعطيل أو حذف الحسابات غير المستخدمة.
- [ ] مراجعة صلاحيات الأدوار (خصوصاً `admin.users` و`admin.backup`).
- [ ] تفعيل `FORCE_PASSWORD_CHANGE=true` مؤقتاً إن لزم.

## 2) الصلاحيات

- 18 صلاحية، 5 أدوار افتراضية، وكل مسار محمي يتحقق من صلاحية محددة.
- الواجهة تخفي العناصر غير المسموحة، لكن **الخادم هو المرجع** — لا تعتمد على الواجهة.
- حساب المتعهد يرى بياناته فقط (يُقيَّد `contractorId` على مستوى الخادم).
- لا يمكن حذف/تعديل الأدوار النظامية (`isSystem`) أو إزالة آخر مدير نظام.

## 3) سجل العمليات (Audit)

- يُسجَّل: إنشاء/تعديل/حذف ساكن، تسكين/إخلاء، تنقلات، طلبات، اعتمادات،
  مستخدمون، إعدادات، نسخ احتياطي/استعادة.
- الحد الافتراضي: 8000 سجل (`AUDIT_LIMIT`).
- متاح للعرض بصلاحية `audit.view` فقط، مع تصفية حسب النوع/المستخدم.
- لا يحتوي السجل كلمات مرور أو توكنات.

## 4) رؤوس الأمان والـ CORS

يرسل الخادم:
```
X-Content-Type-Options: nosniff
X-Frame-Options: DENY
Referrer-Policy: strict-origin-when-cross-origin
Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=()
Cache-Control: no-store        # لمسارات /api/*
```

- `CORS_ORIGINS`: قائمة أصول مفصولة بفواصل، أو `*` عند الحاجة.
- لا تُستخدم Cookies، لذا `allow_credentials=false` ولا خطر CSRF عبر الجلسات.
- التوكن يُخزَّن في `localStorage` (مقبول لتطبيق داخلي مغلق، مع تفعيل HTTPS دائماً).

## 5) الإعدادات الحساسة

| المتغير | ملاحظات |
| --- | --- |
| `SECRET_KEY` | إلزامي وقوي في الإنتاج، وإلا يرفض الخادم الإقلاع |
| `DATABASE_URL` | سرّي، لا يُكتب في الواجهة ولا في Git |
| `STATE_KEY` | `housing_state_v1` — تغييره يعني فقدان الصلة ببيانات الإنتاج |
| `FORCE_PASSWORD_CHANGE` | `true` لإجبار تغيير كلمة المرور عند الدخول |
| `MAX_UPLOAD_MB` | حد الاستيراد (25 افتراضياً) |

- في الإنتاج تُعطَّل `/docs`, `/redoc`, `/openapi.json` تلقائياً.
- يسجّل الخادم تحذيرات عند ضعف المفتاح أو غياب قاعدة البيانات.

## 6) حماية البيانات

- استخدم HTTPS دائماً (Render يوفّره تلقائياً).
- لا تشارك ملف `backup.json` من شاشة الإدارة — يحتوي جميع بيانات السكان.
- خزّن النسخ الاحتياطية في مكان مشفّر ومقيّد الوصول.
- لا تشغّل نسخة محلية بنفس `DATABASE_URL` للإنتاج أثناء عمل الإنتاج (قد تتعارض
  الكتابات؛ المستند يُكتب كاملاً).
- أندرويد: التطبيق يتصل بـ HTTPS فقط افتراضياً. `android:usesCleartextTraffic`
  مفعّل للسماح بالتجربة المحلية على الشبكة — أوقله في نسخة الإنتاج إن أردت.

## 7) الاستجابة للحوادث

1. بدّل `SECRET_KEY` (يُبطل كل الجلسات فوراً) وأعد النشر.
2. بدّل كلمة مرور قاعدة البيانات وحدّث `DATABASE_URL`.
3. راجع سجل العمليات (`/api/admin/audit`) وحدّد النطاق الزمني.
4. استعد نسخة احتياطية موثوقة إن لزم (`/api/admin/restore`).
5. أبلغ المستخدمين وغيّر كلمات المرور المتأثرة.

## 8) قائمة تحقق نهائية

- [ ] `/health` يعمل و`store=postgres`.
- [ ] تسجيل الدخول يعمل بحساب حقيقي، ويفشل بكلمة مرور خاطئة.
- [ ] حساب `security` لا يستطيع فتح شاشة الإدارة.
- [ ] حساب متعهد لا يرى عمال متعهد آخر (جرّب طلباً مباشراً للـ API).
- [ ] تعطيل `/docs` في الإنتاج.
- [ ] نسخة احتياطية حديثة محفوظة خارج الخادم.
- [ ] `CORS_ORIGINS` مضبوط على نطاق الواجهة فقط (بعد الاستقرار).
- [ ] مراقبة السجلات أسبوعياً على الأقل.
